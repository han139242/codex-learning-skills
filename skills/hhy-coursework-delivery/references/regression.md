# 维护与回归检查

先确定变更影响哪些场景，再运行对应工具或实际任务。工具测试、页面审阅和代理行为评测分别记录；格式验证或测试数量不证明成品美观。

## 场景与观察点

1. **另一AI改稿后定稿**：提供老师要求、候选Word及必要数据代码。确认实际候选，保留有效改动；检查符号、公式、图片与代码的一致性，最后版本有可追溯的视觉证据。
2. **模板或篇幅变更**：使用最新要求，保留模板；扩展增加推导或解释，不重复图表、不缩字凑页。“只看看要求”保持只读。
3. **拥挤的表格与目录**：覆盖宽表、长段落、附录和自定义标题样式。检查拆表后的编号对应、横页边界、表头及图题；目录按导航需要取层级，不改坏正文层级，也不误改正文中的“代码目录”。
4. **补充干净的实机截图**：实际运行，重开保存图片核对目标窗口、完整输出、无鼠标和无关浮条；窗口切换或缩放后重新取边界。最终插入尺寸可读，图与题注同页，SEQ不重复，预期异常有解释。
5. **同名文件与提交包**：区分老师规定的邮件主题、附件名和必交格式；保留旧稿并校验哈希，不拆坏相对路径，不发送邮件或正式提交，不删除未知文件。

只检查流程或技能时，不借评测修改正式作业、全局设置或记忆。

## 辅助工具

- `audit_docx.py`：真实文件的只读检查保持输入哈希不变；能识别继承标题、保留代码缩进，并定位文本、公式和图片差异。损坏输入、已有输出或把输出指向输入时须失败且不覆盖。
- `render_word.ps1`：原件不变，在新目录生成Word副本与原生PDF，再以只读方式重开副本，页数一致。测试5.1转交已有7的入口；带目录和无目录短文档均可使用。
- 目录核对覆盖数字、罗马数字、附录及自定义标题，已检查条目数与完整目录一致。缓存页码错误、书签缺失、无目录却指定检查等须明确报错；不支持的定制页码留待人工核对，不报全部通过。
- 元数据命名空间缺失、外部内容域或关系在Word打开前拦截；已有导出目录拒绝覆盖。检查只针对工作副本，不尝试修复原件或关闭用户其他Word实例。
- `compare_pages.py`：相同像素、单像素RGB变化、透明度变化、尺寸变化、增减页分别正确；页号按数字处理，重复页、缺页、空目录明确失败。传入PDF页数后，连续多出的残留旧图也须拦截。

## 安装与记录

修改前备份原文件，先在隔离副本上编辑和验证。检查入口及相对链接、运行技能格式校验，再校验安装文件与已验收副本的哈希；保留无关UI配置、自动触发方式、资料出处和许可。

每次验证记录输入版本、实际命令、结果和未覆盖范围，放在本次任务或备份目录；不往入口累加历史通过次数。不删除或弱化失败测试，不把未做的独立代理评测写成通过。
